# PLAN — Апгрейд csv-to-json.com (01.11.2026)

> Основание: аудит `AUDIT-2026-11-01.md`. Три проблемы, которые решаем: (1) лендинги без инструмента и падающий `app.js`, (2) отсутствует .xlsx при том, что 200 показов/90 дней — это запросы со словом «excel», (3) сайт обещает «JSON для портала GST», которого конвертер не производит.

## 1. Цели и не-цели

**Цели (по возрастанию сложности):**
1. Человек, пришедший из Google на любую страницу, может сконвертировать файл **не уходя со страницы**.
2. Принимаем `.xlsx` напрямую (одна операция вместо трёх, без ручного «Сохранить как CSV» и без проблем с разделителем/кодировкой).
3. Сайт перестаёт обещать то, чего не делает (портальный JSON).
4. Появляется измерение воронки без нарушения privacy-обещания.
5. Убирается каннибализация четырёх одинаковых страниц.

**Не-цели этого этапа:**
- Полноценный генератор GSTR-1 с раскладкой по секциям (B2B/B2CL/B2CS/CDNR) — отдельная фаза 5, решение после данных.
- YAML/XML, «Data Converter Suite» — спроса в GSC ноль.
- Реклама, пейволл-редизайн, Chrome Web Store (канал мёртв: 7 установок при #2 в поиске стора).

### Фаза 1 — Инструмент на лендингах + починка `app.js` + честный текст (6–8 ч)

Это самая ценная фаза: она работает на 152 клика/квартал, которые уже приходят.

**1.1. Рефакторинг `js/app.js` под монтирование (без сборщика).**

Сейчас: top-level `document.getElementById('delimiter').addEventListener(...)` → на лендингах TypeError, всё после строки ~359 (пейволл, счётчик, обработчики) не выполняется.

Станет:

```js
// js/app.js — в конце файла
function initTool(root = document) {
    const get = (id) => root.querySelector('#' + id);
    const els = { dropZone: get('dropZone'), fileInput: get('fileInput'), /* ... */ };
    if (!els.dropZone) return false;        // инструмента на странице нет — молча выходим
    if (els.__initDone) return true;        // защита от двойной инициализации
    els.__initDone = true;
    wireEvents(els);
    updateCounter(els);
    return true;
}
window.CSVtoJSON = { init: initTool, version: '2.0.0' };
document.addEventListener('DOMContentLoaded', () => { initTool(); });
```

Правила рефакторинга:
- Все функции переезжают внутрь модуля или получают `els` первым аргументом — глобальный `els` удаляется.
- Ни одного top-level обращения к DOM. Проверка: `grep -nE "^document\.|^\s*document\.getElementById.*addEventListener" js/app.js` → пусто.
- Поведение на главной не меняется: e2e-набор (см. §4) до и после рефакторинга должен давать одинаковый результат.

**1.2. Единый источник разметки инструмента.**

Разметка инструмента (`<main>` … `#outputSection` + `#paywallModal` + `#toastContainer`) сейчас есть только в `index.html`. Копировать её в 5 лендингов вручную — гарантированный дрейф. Решение: генератор.

- `scripts/build-tool-markup.py` — вырезает блок из `index.html` и пишет `js/tool-markup.js`:
  ```js
  window.CSVtoJSON_MARKUP = "<main class=\"container\">…</main>";
  ```
- `js/tool-mount.js` — по `<div id="toolMount" data-variant="full|gst|nested|batch"></div>`:
  1. вставляет `CSVtoJSON_MARKUP`;
  2. догружает вендоров (PapaParse, JSZip, highlight.js) — см. 1.3;
  3. вызывает `window.CSVtoJSON.init(mount)`;
  4. применяет вариант: `gst` → текст «Drop your GSTR-1 CSV or Excel file», `nested` → сразу раскрывает панель nested mapping, `batch` → `multiple` у input.
- В `index.html` разметка остаётся как есть (не трогаем работающую страницу), а тест `tests/unit/markup-sync.test.js` сверяет хеш: разметка в `js/tool-markup.js` обязана совпадать с блоком в `index.html`. Дрейф ловится тестом, а не глазами.

**1.3. Вендоры на свой домен (заодно чинит ложь в privacy-FAQ).**

Сейчас 4 внешних запроса на unpkg + заявление «единственный внешний запрос — платёжный Worker». Кладём в `vendor/`:
- `vendor/papaparse.min.js` (5.4.1, ~20 КБ gz)
- `vendor/jszip.min.js` (3.10.1, ~30 КБ gz)
- `vendor/highlight.min.js` + `vendor/json.min.js` (~10 КБ gz)
- `vendor/xlsx.full.min.js` (SheetJS 0.20.x, ~260 КБ gz) — **только лениво**, при первом .xlsx (см. Фаза 2).

Итог: страница грузится с одного домена, «works offline» становится правдой, скорость выше, приватностный клейм становится буквально верным.

**1.4. Встраивание на лендинги.**

| Страница | Что делаем |
|---|---|
| `/csv-to-json-for-gst` | `<div id="toolMount" data-variant="gst">` **сразу под H1**, статья остаётся ниже без изменений |
| `/convert-csv-to-json` | вариант `full`, тот же паттерн |
| `/csv-to-nested-json` | вариант `nested` (панель dot-notation раскрыта) |
| `/csv-to-json-batch` | вариант `batch` (`multiple`) |
| `/csv-to-json` | см. Фазу 3 (канонизация), инструмент не встраиваем |

Обязательное условие: H1, title, description, первые абзацы и структура H2 на GST-странице **не меняются** — она держит позицию 8.1, риск сломать её недопустим. Вставка аддитивная.

**1.5. Честный текст вместо обещания портального JSON.**

Сейчас на GST-странице: «get valid JSON, and upload it to the portal». Портал принимает только JSON собственной схемы (`gstin`, `fp`, секции `b2b`/`b2cl`/`b2cs`/`cdnr`) — наш вывод это массив объектов с именами колонок. Человек сделает всё верно и получит отказ при загрузке.

Правки:
- Заменить «upload to the portal» на «JSON для вашей бухгалтерской программы, API или собственного импорта».
- Добавить в FAQ отдельный пункт: «Does the GST portal accept this JSON?» — прямой ответ: нет, портал принимает только файл своей схемы, который генерирует GST Offline Tool; наш JSON нужен для API/BI/своего импорта.
- В `<details>` про Excel — оставить двухшаговый путь до Фазы 2, потом переписать.

**Готово, когда:** на всех 5 страницах можно бросить файл без перехода; в консоли нет ошибок; тесты зелёные; H1/title GST-страницы побайтово те же.

### Фаза 2 — Настоящий .xlsx (6–8 ч)

**2.1. Ленивая загрузка библиотеки.**

```js
// js/xlsx-loader.js
let p;
function loadXLSX() {
    if (window.XLSX) return Promise.resolve(window.XLSX);
    p = p || new Promise((res, rej) => {
        const s = document.createElement('script');
        s.src = 'vendor/xlsx.full.min.js';
        s.onload = () => res(window.XLSX);
        s.onerror = () => rej(new Error('Не удалось загрузить модуль Excel'));
        document.head.appendChild(s);
    });
    return p;
}
```

Никакие 260 КБ не грузятся, пока человек не кинул .xlsx. Пользователь CSV вообще не платит за эту фичу.

**2.2. Парсинг и унификация.**

- Источник — рабочий код из `backup-rollback-excel-2026-08-07/js/app.js` (`isExcelFile`, `parseXlsxFile`), но переписанный: `sheet_to_json(ws, {header:1, raw:true, defval:null})` → приводим к тому же виду, что отдаёт PapaParse (`{data, meta.fields}`) → дальше **общий конвейер** (типизация, nested mapping, batch, ZIP). Никаких отдельных веток в трёх местах, как было раньше: одна точка входа `readTable(file)`.
- **Выбор листа** (новое, и это реальная боль GST-файлов — в книге несколько секций): после чтения книги, если листов > 1, показываем селект «Sheet: [B2B ▾]» и перечитываем при смене. По умолчанию первый непустой.
- Ограничения: .xls (старый бинарный) — поддерживается SheetJS, оставляем; лимит 20 МБ с понятным сообщением.
- `accept=".csv,.tsv,.txt,.xlsx,.xls"`; drop-зона принимает всё, тип определяется по расширению и первым байтам (PK — это zip/xlsx).

**2.3. Тексты и SEO после включения Excel.**
- Title GST-страницы: `Excel to JSON for GSTR-1 — GST Converter (XLSX & CSV) | Free` — теперь обещание правдиво.
- Убрать из FAQ фразу «конвертер не читает .xlsx напрямую», заменить на «кидайте книгу как есть, лист выбирается в один клик».
- Description: убрать «(.xlsx via CSV)».

**2.4. Тесты Excel (см. §4):** фикстура-книга на 3 листа с проверкой: заголовки, типы (числа/пустые/даты), выбор листа, кириллица/хинди в ячейках, CSV-строка с точкой с запятой.

**Готово, когда:** .xlsx конвертируется на главной и на GST-странице, выбор листа работает, в GSC через 7 дней виден рост CTR по кластеру «excel».

### Фаза 3 — Канонизация дублей (1–2 ч)

GitHub Pages не поддерживает 301. Поэтому:

| Страница | Действие |
|---|---|
| `/csv-to-json` | `<link rel="canonical" href="https://csv-to-json.com/">`, убрать из sitemap, ссылки в навигации ведут на `/` |
| `/convert-csv-to-json` | то же (страницу оставить — она ранжируется, но не должна конкурировать) |

**Готово, когда:** sitemap содержит 5 URL, у каждого canonical на себя или на главную; в GSC «Page with redirect / Duplicate» не растёт.

### Фаза 4 — Измерение воронки без нарушения privacy (3–4 ч)

**4.1. Эндпоинт в существующем Worker** (не новый сервис):

```js
// csvtojson-payment-worker.js — новый маршрут
// POST /t  { e: "convert_click", p: "/csv-to-json-for-gst" }
// KV-счётчики вида counter:2026-11-01:convert_click:/csv-to-json-for-gst
```

Что НЕ пишем: IP, User-Agent, cookies, fingerprint. Только имя события, путь страницы и дата.

**4.2. События (6 штук, больше не надо):** `page_view` (только лендинги + главная), `file_loaded` (+тип csv/xlsx), `convert_click`, `download_click`, `paywall_shown`, `payment_verified`.

**4.3. Правка privacy.html и FAQ:** «Мы не используем сторонние счётчики и не пишем cookies. Считаем шесть анонимных событий на своём сервере — без IP, без cookie, без содержимого ваших файлов». Это сильнее, чем текущая формулировка, и правда.

**4.4. Отчёт:** `scripts/funnel-report.py` — сводка за 7/30 дней таблицей в консоль и в Telegram (по желанию — кроном раз в неделю).

**Готово, когда:** на проде видны все 6 событий, счётчики растут, privacy-текст соответствует фактам.

### Фаза 5 — GATE: GSTR-1-режим (решение после 2 недель данных)

Решаем по цифрам, а не по ощущению. Триггер «идём»: **≥40 событий `paywall_shown` за 14 дней** ИЛИ рост CTR кластера «excel» ≥2x. Иначе — не идём, остаёмся конвертером.

Если идём (3–5 дней, отдельный план):
- Разбор книги по листам/колонкам, классификация строк в секции `b2b` / `b2cl` / `b2cs` / `cdnr`.
- Валидация: контрольная сумма GSTIN, формат периода `MMYYYY`, дата `DD-MM-YYYY`, ставки только из разрешённого набора, порог B2CL 2.5 лакха, inter/intra по POS.

- Дисклеймер: инструмент не заменяет проверку в Offline Tool; финальная ответственность на налогоплательщике.
- Отдельный набор тестов на каждое правило валидации (это деньги и штрафы пользователя, тут цена ошибки максимальна).

## 4. Тестовая стратегия

Ни одного теста в проекте нет — это придётся создать, иначе мы снова будем править живой сайт на ощупь.

**Unit (node, без зависимостей):** `tests/unit/`
- `read-table.test.js` — CSV/TSV/;разделитель/BOM/кавычки/пустые строки → одинаковый результат.
- `xlsx-map.test.js` — SheetJS-выгрузка → `{data, meta.fields}`, выбор листа, типы.
- `nested.test.js` — dot-notation: `address.city`, `items.0.title`, конфликты ключей.
- `types.test.js` — number/boolean/null/leading-zero строки («00721» не должен стать 721).
- `markup-sync.test.js` — хеш разметки в `js/tool-markup.js` == блок в `index.html`.
- `guards.test.js` — `initTool()` на странице без инструмента: не бросает, возвращает false.

**E2E (реальный Chrome через CDP, локальный статический сервер `python -m http.server`):** `tests/e2e/`
- Главная: drop CSV → превью → convert → скачивание, счётчик 5→4, пейволл на 6-й.
- Главная: .xlsx из фикстуры, выбор листа, batch из 3 файлов → ZIP.
- Лендинг GST: инструмент есть, drop работает, конверсия не требует перехода.
- Лендинг GST: **в консоли ноль ошибок** (сейчас там ReferenceError).
- Мобильный вьюпорт 390×844: drop-зона кликабельна, файл-пикер работает.

**Live-набор (после деплоя):** `tests/e2e/live.js` — те же 5 проверок против `csv-to-json.com` + проверка, что H1/title GST-страницы не изменились (сравнение с сохранённым хешем).

Прогон: `node tests/unit/run.js` и `node tests/e2e/run.js --local|--live`. Обе команды должны быть в состоянии «0 FAIL» до деплоя и после.

- Позиция GST-страницы упала ниже 12 и не восстановилась за 14 дней → откат Фазы 1 к baseline-коммиту.
