## Что это за проект

Browser-side конвертер CSV/Excel → JSON плюс инструмент GSTR-1 JSON → Excel. Домен **csv-to-json.com**, хостинг GitHub Pages ($0), платежи USDT TRC-20 через Cloudflare Worker.

Экономика без иллюзий (`PLAN-UPGRADE-2` §8): потолок ~300–450 кликов/квартал, при конверсии 1% и цене $5 это $20–25 в квартал. За всё время проект принёс $5. **Проект — учебно-инфраструктурный полигон**, а не источник дохода: на нём обкатаны SEO-сниппеты, счётчик воронки, работа с каналами и TDD для статики.

## Git: где живёт какая история

Обнаружено 14.11.2026 — у локального репозитория **не было ни одного remote**. Все коммиты с 01.11 жили только на диске, а на GitHub файлы попадали через `scripts/deploy.py` (Contents API) — каждый деплой создавал там отдельный коммит.

| Ветка | Что содержит | Кто пишет |
|---|---|---|
| `main` на GitHub | **плоская прод-структура** (файлы сайта в корне), 143 коммита с августа | `scripts/deploy.py`, по одному коммиту на деплой |
| `source` на GitHub | **исходники**: `seo/*.html`, тесты, скрипты, доки | `git push origin master:source` из локального `master` |
| локальный `master` | то же, что `source` | коммиты вручную |

**Почему две ветки, а не одна:** Pages настроен на `main` + `/` (корень). Локальные исходники лежат в `seo/`, и деплой раскладывает их в корень. Слить истории в одну нельзя — git увидит `seo/x.html` и `x.html` как разные файлы и создаст дубли в проде. Поэтому `main` остаётся артефактом деплоя, а история разработки живёт в `source`.

**Правило:** после работы — `git push origin master:source`. Remote `origin` теперь настроен (`https://github.com/makszoom/csvtojson.git`), но `gh` не авторизован — push идёт с токеном из `.env`.

## Уроки проекта (не повторять)

1. **GSC не перечитывает sitemap сам.** Карта csv-to-json.com стояла с 2026-09-20, пока файл рос с 5 до 10 URL — все изменения были для Google невидимы. После любой правки sitemap — `PUT` через Sitemaps API (`gsc-resubmit-sitemap.py`), иначе новые страницы ждут месяцами.
2. **Тестовый трафик нельзя мерить вместе с живым.** Live-E2E писал в тот же счётчик: дни 06.11 (101 просмотр) и 11.11 (75) — это были мои прогоны, а не люди.
3. **Ссылки в GitHub README — `rel="nofollow"`.** PR в awesome-списки дают бренд и краулинг, но не ссылочный вес. Проверять `rel` до того, как планировать канал бэклинков.
4. **Перед PR в чужой список** проверять три вещи: дату последнего коммита, мержатся ли PR за последние месяцы, и нет ли в CONTRIBUTING запрета на тип продукта. `free-for.dev` прямым текстом запрещает конвертеры; `awesome-privacy-tools` мёртв с 2024 года.
5. **Никогда не обещать portal-готовый JSON.** Портал принимает только JSON своей схемы GSTR-1, его делает официальный Offline Tool. Обещание жило в 4 местах (видимый текст, FAQ, JSON-LD, og/twitter) — `claims.test.js` держит регрессию.
6. **Внутренние доки не должны попадать на публичный сайт.** `PLAN-UPGRADE-2` однажды уехал в прод; теперь `SKIP_PREFIX` в `deploy.py` это блокирует.
7. **Усиливать ранжирующуюся страницу, а не тиражировать новые.** 97% трафика с одной страницы в полосе 7–9: подъём её на 4-е место даёт больше, чем пять новых страниц.
